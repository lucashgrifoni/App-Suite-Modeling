# Internacionalização (i18n) — documento canónico

**Idiomas:** **pt-BR** e **en** na UI principal (`apps/web`), exportações Markdown/PDF no servidor e cliente, e relatório premium (API + CLI).

**Ficheiros centrais (referência rápida):**

| Área | Onde |
|------|------|
| Política Web + storage | `apps/web/src/i18n/localePolicy.ts`, `apps/web/src/i18n/i18n.ts`, `otm.web.locale` |
| Locale de artefactos (UI → API) | `apps/web/src/i18n/exportArtifactLocale.ts` |
| Normalização única (Python) | `packages/exporters/otm_exporters/export_locale.py` |
| Premium | `packages/report-premium/otm_report_premium/i18n_locale.py`, `report_i18n.py`, builder/render |
| Cópias UI | `apps/web/src/i18n/locales/en.json`, `pt-BR.json` |

---

## 1. Decisões — UI (React)

- **Biblioteca:** `i18next` + `react-i18next`; `escapeValue: true`; `Trans` para marcação segura.
- **Allowlist:** só `pt-BR` e `en` (`SUPPORTED_LOCALES`).
- **Primeira visita:** `localStorage['otm.web.locale']` válido → usar; senão `navigator.languages`: prefixo `pt` → **pt-BR**; caso contrário **en**.
- **Fallback i18next:** `fallbackLng: "en"`; em DEV `parseMissingKeyHandler` loga chave ausente.
- **Persistência:** `languageChanged` → normalização com `parseStoredLocale`.
- **Segurança:** sem `dangerouslySetInnerHTML` na camada de tradução; erros de parse no Diff usam `i18n.t` no throw.

---

## 2. Decisões — exportações e API

- **`POST /v1/exports`:** campo opcional `locale`; omissão mantém **pt-BR** (retrocompatibilidade); valor **presente e inválido** → normalizado (tipicamente **en** após regras em `export_locale.py`).
- **Segurança:** locale não compõe caminhos nem nomes de template; só literais normalizados.
- **Tipagem:** `ExportArtifactLocale = Literal["pt-BR", "en"]` (Python) alinhado a OpenAPI / TS.
- **Testes:** cobertura de strings em pytest (Markdown EN) + Vitest (`localePolicy`, `exportArtifactLocale`) + API; E2E de PDF continua a validar bytes/extensão, não texto interno.

---

## 3. Política de locale (resumo)

### Cliente (`apps/web`)

1. Exportação: **Idioma do artefacto** (seguir UI / pt-BR / en), quando aplicável.
2. Caso contrário: idioma ativo da UI.
3. Valores inválidos: `localePolicy` / `exportArtifactLocale`.

### Servidor

| Endpoint | `locale` omitido | Inválido |
|----------|------------------|----------|
| `POST /v1/exports` | `pt-BR` | normalizado (ver `export_locale`) |
| `POST /v1/reports/premium` | `pt-BR` | normalizado |

**Variantes BCP47 comuns** (`pt`, `pt_br`, `en-US`, …) colapsam para `pt-BR` ou `en` numa única implementação em `export_locale.py`. O premium reexporta a mesma lógica via `i18n_locale.py`.

---

## 4. Cobertura bilíngue

| Superfície | pt-BR | en |
|------------|-------|-----|
| UI principal | Sim | Sim |
| Export Markdown (`document_markdown`, `analysis_markdown`) | Sim | Sim |
| PDF resumo (jsPDF, cliente) | Sim | Sim |
| Report premium MD/HTML/PDF | Sim | Sim |
| CLI `otm report` | Sim (`--locale`) | Sim |

### Onde o premium aplica `locale`

Builder (`build_premium_report_payload`), render MD/HTML, corpo `PremiumReportBody` na API, `fetchPremiumReport` na web. Mensagens de erro `PREMIUM_REPORT_INPUT` respeitam o locale pedido.

---

## 5. Não traduzido (intencional)

- Dados do motor: títulos de ameaças, `next_step` do backlog, enums técnicos.
- Mermaid / JSON cru sem template de relatório.
- **CLI Typer:** `--help` e algumas mensagens de sucesso permanecem em português nesta fase.
- **OpenAPI / Swagger:** descrições em inglês (convenção de documentação de API).

---

## 6. Limitações conhecidas

1. **Motor / backlog** — texto gerado pelo `otm_threat_engine` ou catálogos permanece predominantemente em inglês técnico; só templates de apresentação são bilíngues.
2. **Roadmap premium** — `priority_label` (`urgent`, `high`, …) reflete o motor; não traduzido na string agregada.
3. **CLI** — ver secção 5; o relatório em si respeita `--locale`.
4. **E2E** — `playwright.config.ts` usa `locale: "pt-BR"` para estabilidade; não há suíte que percorra toda a UI em EN com asserções de cópia em cada ecrã. Timeouts intermitentes em `e2e/pdf.spec.ts` (download) não são específicos de i18n.
5. **PDF binário no E2E** — valida-se `%PDF` / geração; conteúdo textual coberto em testes unitários (MD/HTML).
6. **Mermaid** — sem camada extra de tradução de rótulos além do já existente nos exportadores Markdown.

---

## 7. Glossário mínimo

| Termo | Significado |
|-------|-------------|
| **Locale** | `pt-BR` ou `en` após normalização. |
| **Artefacto** | Ficheiro ou corpo HTTP entregue ao utilizador (Markdown, PDF, …). |
| **Texto estrutural** | Cabeçalhos, disclaimers, nomes de secção — traduzível. |
| **Conteúdo dinâmico** | Ameaças, métricas cruas do motor — não traduzido automaticamente. |
| **`normalize_export_locale`** | `export_locale.py` — exports. |
| **`normalize_premium_locale`** | `i18n_locale.py` — premium. |

**Chaves Web:** `export.*`, `artifactPdf.*` nos JSON em `apps/web/src/i18n/locales/`.
